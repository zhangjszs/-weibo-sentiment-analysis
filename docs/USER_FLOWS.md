# 用户任务与验收指标 (User Flows)

> 本文档定义系统唯一主任务和验收指标。前端信息架构围绕此任务展开。

## 唯一主任务

**选择微博话题和时间范围 → 查看摘要 → 下钻分析 → 导出报告**

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  1. 选择话题  │ →  │  2. 查看摘要  │ →  │  3. 下钻分析  │ →  │  4. 导出报告  │
│  + 时间范围   │    │  + 来源说明   │    │  文章/评论/   │    │  PDF/Markdown │
└─────────────┘    └─────────────┘    │  情感/传播    │    └─────────────┘
                                      └─────────────┘
```

## 详细步骤

### Step 1: 选择话题和时间范围
- 用户在首页输入微博话题（关键词）
- 选择时间范围（默认最近 7 天）
- 点击「开始分析」

### Step 2: 查看摘要
- 系统展示一句话结论
- 显示数据范围（时间范围、数据量）
- 显示数据来源（真实数据 / 演示数据 / 实验能力）
- 显示模型/规则版本
- 显示局限性说明

### Step 3: 下钻分析
- 文章列表（按热度/时间排序）
- 评论列表（支持分页）
- 情感分布（正面/中性/负面）
- 传播路径摘要
- 热词与趋势

### Step 4: 导出报告
- 报告包含：摘要、数据范围、来源说明、局限性、生成时间
- 支持 PDF / Markdown 格式
- 报告关联分析快照 ID，可追溯到原始数据

## 验收指标

| 指标 | 标准 | 验证方式 |
|------|------|----------|
| **主任务完成** | 用户能从一个入口完成一次话题分析并看到来源说明 | 浏览器验收 |
| **可信性** | 所有数值都能显示时间范围、数据量、数据源和模型/规则版本 | 响应 `meta` 字段检查 |
| **空数据** | 没有数据时显示原因和下一步，不显示 0 作为伪结果 | 空库验收 |
| **报告** | 导出内容包含摘要、数据范围、来源说明、局限性和生成时间 | 报告内容检查 |
| **响应时间** | 摘要首屏 < 3s（真实数据），空数据 < 1s | 性能测试 |
| **可复现** | 相同话题 + 时间范围刷新后结果一致 | 重复请求验收 |

## 四种系统状态

系统必须对以下四种状态给出可解释结果：

| 状态 | 预期行为 |
|------|----------|
| **真实数据** | 展示分析结果 + `provenance: real` |
| **演示数据** | 展示模拟数据 + `provenance: demo` + 演示标识 |
| **空数据** | 显示「暂无数据」+ 原因 + 下一步建议 |
| **后端依赖不可用** | 显示降级说明 + `limitations` + 不伪造数据 |

## 错误处理原则

- 接口 500 → 显示「分析服务暂时不可用」，不显示技术堆栈
- 接口 401/403 → 引导重新登录
- 接口 404（无数据）→ 显示空态 + 采集建议
- 接口 503（降级）→ 显示部分结果 + 降级说明
