### P3.2 - 修复已发现的 Bug（中 ROI，0.5-1 天）

测试过程中发现了 2 个真实 bug，按严重程度排序：

#### Bug 1：FTS5 索引替换不生效（search_service）✅ 已修复（`44d2cd0`）

- **位置**：`src/services/search_service.py` [index_document](file:///d:/Coding/Projects/微博舆情分析/src/services/search_service.py#L241-L247) 和 [batch_index](file:///d:/Coding/Projects/微博舆情分析/src/services/search_service.py#L284-L290)
- **问题**：`INSERT OR REPLACE INTO search_fts` 不生效。FTS5 虚拟表默认以 `rowid` 为主键，`id` 只是普通列。替换文档时旧 FTS 条目不会被删除，旧标题/内容仍可被搜到。
- **修复方案**：INSERT 之前先 `DELETE FROM search_fts WHERE id = ?`（已落地，覆盖 index_document 与 batch_index 两处）
- **影响**：搜索结果可能包含已删除/更新的旧内容，用户体验问题
- **预估**：1-2 小时

#### Bug 2：total=0 时 progress > 100%（task_status_service / nlp_task_service）✅ 已修复（`7806eb8`）

- **位置**：`src/services/task_status_service.py` [_query_local_task](file:///d:/Coding/Projects/微博舆情分析/src/services/task_status_service.py#L44-L47)，`src/services/nlp_task_service.py` 类似位置
- **问题**：`int(info.get("total", 1) or 1)` 中 `0 or 1` 求值为 1，所以 `total=0` 被当 1 处理。当 `current > 0` 时 progress 可能超过 100（如 5/1*100=500）。
- **修复方案**：改为 `max(int(info.get("total", 1) or 1), 1)` 是多余的——实际问题是 total 为 0 意味着任务还没开始，progress 应该是 0 而不是除零。可以加判断：`total == 0 ? 0 : int(current / total * 100)`（已落地：`total = int(info.get("total", 1) or 0)` + `progress = int(current/total*100) if total > 0 else 0`）
- **影响**：前端进度条显示异常（超过 100%）
- **预估**：0.5 小时

## 五、代码规范与约定

### 提交信息规范

使用 conventional commits 格式：

```
feat: 新功能
fix: 修复 bug
refactor: 重构（不改变功能）
test: 测试相关
docs: 文档
chore: 构建/工具链
```

例子：
```
test(spider-task): expand spider_task_service tests to 73 cases
fix(search): FTS5 index replacement not working on doc update
```

### 测试编写规范

参考已完成的 `test_spider_task_service.py` / `test_search_service.py`：
- 文件开头写清楚测试策略、覆盖范围、历史背景
- 用 class 分组，每组有明确的 docstring
- 每个测试有中文 docstring 说明测什么
- mock 外部依赖，不碰真实数据库/HTTP/Celery
- 用 `tmp_path` 等 pytest fixture 隔离测试数据
- 发现 bug 但暂不修时，写测试记录实际行为 + 注释说明

### 模块拆分规范

拆上帝文件时遵循：
- **对外 API 不变**：在 `__init__.py` 里 re-export，保证 import 路径兼容
- **按职责拆**：不是按行数硬拆，而是按功能领域拆
- **先补测试再拆**（如果能补的话），保证重构不破坏功能
