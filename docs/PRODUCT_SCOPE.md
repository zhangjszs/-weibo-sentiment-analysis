# 产品范围 (Product Scope)

> 本文档定义微博舆情分析系统 v1 的产品能力边界。任何功能只能属于且仅属于一类。
> 首页主导航只展示「正式能力」，实验与演示能力收口到独立的「实验/运维」区域。

## 分类原则

| 分类 | 含义 | 用户可见性 | 数据要求 |
|------|------|-----------|----------|
| **正式能力** | 默认承诺、可演示、可维护 | 主导航 | 真实数据或显式空态 |
| **实验能力** | 代码存在、可运行，但不承诺稳定性 | 实验区域，带标识 | 真实但可能不完整 |
| **演示能力** | 仅用于演示/测试，需显式开关 | 演示环境或 `demo=true` | 模拟数据，必须带标识 |

## 正式能力 (v1 主链路)

以下能力构成 v1 唯一主任务，新用户应能在 5 分钟内完成一次：

1. **微博文章/评论采集** — 基于 `WEIBO_COOKIE` 的真实采集（`spider/`）
2. **情感分析** — SnowNLP + 情感词典 + 启发式规则（`sentiment_service/`）
3. **热词/趋势** — 基于已采集文章的热词统计与时间趋势
4. **地域分布** — 基于评论 IP 的地域聚合
5. **传播摘要** — 基于转发/评论关系的传播分析（`propagation_analyzer.py`）
6. **报告导出** — 基于分析快照生成摘要报告（`report_generator.py`）
7. **用户认证** — 登录/登出、JWT + Cookie 双鉴权
8. **审计日志** — 关键操作记录（`audit_service.py`）
9. **预警规则** — 基于情感/热度的阈值预警（`alert_service.py`）

## 实验能力

以下能力代码存在、可独立运行，但**不承诺数据完整性和接口稳定性**：

1. **多平台采集框架** — 抖音/知乎/B站/微信采集器（`platform_collectors/`）
   - 知乎：基于公开 API，可能受反爬限制
   - 抖音/B站/微信：基于外部搜索 API，稳定性不承诺
2. **BERT 情感模型** — 本地 ONNX 推理（`sentiment_backend.py`），需额外模型文件
3. **上下文情感分析** — `contextual_sentiment.py`，实验性特征
4. **协作功能** — `collaboration_service.py`，多人协作标注
5. **WebSocket 实时推送** — `websocket_service.py`，实验性
6. **LLM 增强分析** — `ml_routes.py`，需外部 LLM API Key

## 演示能力

以下能力仅在显式开关或演示环境启用：

1. **演示数据 Provider** — 显式 `demo=true` 或 `FLASK_ENV=demo` 触发
2. **演示管理员账户** — `AUTO_CREATE_DEMO_ADMIN=True` 时创建

## 明确不做（v1）

- 不做多平台真实采集的正式承诺（仅微博）
- 不做实时 WebSocket 作为主链路
- 不做 ML 模型线上化（训练与推理分离）
- 不做消息队列（Celery）作为默认依赖
- 不做前端状态管理库迁移（保持 Pinia）
- 不做微服务拆分（保持 Flask 单体）

## 数据来源标识规则

所有分析响应必须通过 `meta` 字段携带来源信息：

- `source_type`: `real` | `demo` | `experimental`
- 正式模式**绝不**静默返回 mock 数据
- 演示数据必须由显式开关触发，并在响应中携带 `is_demo: true`
- 实验能力返回 `experimental` 类型，前端必须显示实验标识
